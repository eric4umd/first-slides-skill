# 页型库

> 跟 `scripts/build.py` 里的页型表是同一张：`python3 scripts/build.py --types` 也能看。

每一页在 content.md 里是一行 `## 第几页讲什么`（不上屏，查账用它认页），下面跟一个 ```yaml 块，第一行 `type:` 写页型。每个页型都能写：`title` 一句判断（必写）、`kicker` 眉题、`stand` 导语（一行）、`notes` 讲者备注（0–8 条，只在按 N 和讲者窗口里出现，手机版不显示）、`turn` 翻进来的做法（一般不写，引擎按前后两页自己配）。

**提示页上看得见哪几句**：8 种提示页都不显示 `stand`，它只在手机版里出现。`cue`、`cue3`、`cueline`、`cuebridge`、`cueshift` 页面上显示 `title`；`cueask`、`cuepick`、`cuecalc` 不显示，`title` 只在讲者窗口和手机版里当这一页的名字，页面上最显眼的那句，cueask、cuepick 是 `lead`，cuecalc 是 `result.label` 和 `sub`。用户说改某页的“标题”，改他在那一页上看到的那句。

**先用前 8 种“提示页”**：一页一个主角，细节进 notes。后面 18 种“图表页”是一页放一张完整的图，数据页需要时再用。这份文件很长，先读到“## 图表页”那一行为止就够，用到哪种图表页再往后查那一节。

尖括号 `<…>` 里换成材料里的东西；材料里没有的不写、不编。

## 提示页（8 种）

### cue — 提示页：一句引子 + 一个大数 + 一句判断（标题），点一下出一条安静的小图

一页一个大数。结果页、最好的一次、踩过的坑、做到几个目标、哪一步掉人，都用它。

- `big.v` 是页面上最大的那个数，写成字符串保留格式（`'2,750'`、`'12.4'`）；`unit` 单位；`sign: '+'` 显示正号。负数直接写 `v: '-1,000'`，或者写 `sign: '−'` 加 `v: '1,000'`，两种都会显示负号；正负号只写在一处，两处都写查账会报错。
- `tone`：`good` 好消息用强调色；`bad` 坏消息用墨色斜纹；`plain` 中性。不写当 `good`。
- `pre: 约` 放在数前面，预测、估算的数写“约”，精确数写进 `exact` 给查账对。`unit` 以“万”开头时，`exact` 写成元：页面写 `100.1` 万，`exact` 写 `1001000`。
- `lead` 大数上面那句引子，`title` 大数下面那句判断（这一页要对方记住的话），`sub` 再下面一行小字。
- 右边那一栏四选一（都不写就是封面那种底板，`band: false` 连底板也不要）：
  - `strip: {kind: bars, v: [..], hiFrom: 第几个起强调, labels: [{at, text, hi}]}`：一排竖条，比如每月数；
  - `strip: {kind: steps, steps: [{label, v}], hi: 第几步强调（从 0 数）}`：一步步还剩多少；
  - `strip: {kind: dots, items: [{label, ok: true/false, src}]}`：几个目标，做到没做到；
  - `pair: [{label, v, unit, hi, src}, {…}]`：两块竖块比一对数。
- strip 要点一下（→）才出来；pair 和底板翻进来就在。
- `title`、`lead`、`sub` 都要一行放得下（标题约 38 个汉字），放不下查账报“错”。

<details><summary>字段</summary>

- `lead`：文字（可不写）
- `big`：一组：
  - `sign`：文字（可不写）
  - `pre`：文字（可不写）
  - `v`：数或文字（原样显示）
  - `exact`：数（可不写）
  - `unit`：文字（可不写）
  - `tone`：文字（可不写）
  - `src`：文字（可不写）
  - `how`：文字（可不写）
- `sub`：文字（可不写）
- `band`：见下面说明（可不写）
- `pair`：一串，2 个（可不写），每个写：
  - `label`：文字
  - `v`：数或文字（原样显示）
  - `unit`：文字（可不写）
  - `hi`：true / false（可不写）
  - `src`：文字（可不写）
- `strip`：一组（可不写）：
  - `kind`：文字
  - `v`：一串数，4–31 个（可不写）
  - `hiFrom`：数（可不写）
  - `labels`：一串，0–4 个（可不写），每个写：
    - `at`：数
    - `text`：文字
    - `hi`：true / false（可不写）
  - `steps`：一串，3–5 个（可不写），每个写：
    - `label`：文字
    - `v`：数
  - `hi`：数（可不写）
  - `items`：一串，3–6 个（可不写），每个写：
    - `label`：文字
    - `ok`：true / false
    - `src`：文字（可不写）
  - `src`：文字（可不写）

</details>

```yaml
type: cue
kicker: <这一页在讲什么，一小行>
lead: <引子，说到大数为止，比如“今年……比去年多”>
big:
  sign: '+'
  v: '<大数>'
  unit: <单位>
  tone: good
  src: <这个数从哪个文件、哪一栏来的>
  how: <怎么算出来的，比如“今年合计 − 去年合计”>
title: <一句判断，对方听完要记住的话>
notes:
- <讲的时候要说、但不放在页面上的：口径、细节、谁做了什么>
- <材料里推不出来的写“待定”>
```

### cue3 — 核心论证：标题是主张，三列各一个数 + 一句话

核心论证：标题是主张，下面 2–3 列各一个数撑着它。“为什么说是 X 带来的”“哪些做法能接着用”。

- 每列 `v` 一个数，`text` 一句话说这个数是什么，`sub` 一行小字（对照、时间段）。
- `v` 写成 `'92 → 143'` 会画两根横条比前后；`unit` 是“人”且是整百整千的数，会画一片小格子（`gridUnit` 换成别的单位，`grid: false` 不画）。
- 标题写主张；会被追问的（“会不会本来就在涨”）写进 notes，连回答一起。

<details><summary>字段</summary>

- `items`：一串，2–3 个，每个写：
  - `v`：数或文字（原样显示）
  - `sign`：文字（可不写）
  - `unit`：文字（可不写）
  - `tone`：文字（可不写）
  - `text`：文字
  - `sub`：文字（可不写）
  - `src`：文字（可不写）
  - `how`：文字（可不写）
  - `gridUnit`：文字（可不写）
  - `grid`：true / false（可不写）

</details>

```yaml
type: cue3
kicker: <为什么这么说>
title: <主张>
items:
- v: '<数>'
  unit: <单位>
  text: <这个数是什么>
  sub: <对照或时间段>
  src: <出处>
- v: <前> → <后>
  unit: <单位>
  text: <…>
  src: <出处>
- v: '<数>'
  unit: <单位>
  text: <…>
  src: <出处>
```

### cueline — 数据页：一条线占满整页，只标转折和前后两段平均

一条线占满整页：什么时候变的。只标一个转折和前后两段平均。

- `series` 6–31 个点；开头信息写了 `period: 月` 时，`start` 是第一个点是几月，`event.at`、`avg` 的 `from`/`to` 都写月份。
- `avg` 正好两段，查账会重算平均，跟标题对不上会提醒。`avgDigits` 平均数几位小数，不写就取整，都按四舍五入（24.55 显示 24.6）；标题里的平均带小数（比如 12.4），就写 `avgDigits: 1`，不然查账对不上。
- `max` 纵轴顶（不写按 500 取整，数小的时候写上，比如 35），`maxStep` 取整的步长。

<details><summary>字段</summary>

- `series`：一串数，6–31 个
- `event`：一组：
  - `at`：数
  - `text`：文字
- `avg`：一串，2 个，每个写：
  - `from`：数
  - `to`：数
  - `label`：文字
  - `how`：文字（可不写）
- `unit`：文字（可不写）
- `max`：数（可不写）
- `src`：文字（可不写）
- `start`：数（可不写）
- `avgDigits`：数（可不写）
- `maxStep`：数（可不写）

</details>

```yaml
type: cueline
kicker: <每月什么数 · 口径>
title: <什么时候起，从平均多少变到多少>
series: [<每个月的数>, …]
start: 1
event:
  at: <转折那个月>
  text: <那个月发生了什么>
avg:
- from: <月>
  to: <月>
  label: <前一段平均>
- from: <月>
  to: <月>
  label: <后一段平均>
unit: <单位>
src: <出处>
```

### cuebridge — 数据页：多出来的从哪来，一项一格，柱子只画变化那一截（hi 那项强调色，往下走的斜纹）

多出来的从哪来：从去年到今年，一项一项加。

- `start`、`end` 两头，`steps` 2–5 项，每项 `v` 是这一项多了（负数是少了）多少；查账会对 start + 各项 = end。
- `hi: true` 那项用强调色（主角那项）；往下走的项画斜纹。
- `lo`、`hi` 纵轴从多少到多少（不从 0 起，把变化那截放大），`digits` 小数位。

<details><summary>字段</summary>

- `start`：一组：
  - `label`：文字
  - `v`：数
  - `src`：文字（可不写）
- `end`：一组：
  - `label`：文字
  - `v`：数
  - `src`：文字（可不写）
- `steps`：一串，2–5 个，每个写：
  - `label`：文字
  - `v`：数
  - `hi`：true / false（可不写）
  - `src`：文字（可不写）
- `lo`：数
- `hi`：数
- `unit`：文字（可不写）
- `digits`：数（可不写）

</details>

```yaml
type: cuebridge
kicker: <多出来的 X · 按什么拆>
title: <多出来的里面，哪一项占了多少>
start:
  label: <去年>
  v: <数>
  src: <出处>
end:
  label: <今年>
  v: <数>
  src: <出处>
steps:
- label: <一项>
  v: <多了多少>
  hi: true
  src: <出处>
- label: <另一项>
  v: <多了多少，少了写负数>
  src: <出处>
lo: <纵轴起点>
hi: <纵轴顶>
unit: <单位>
```

### cueshift — 数据页：钱从哪挪到哪，去年今年两根长条，同一项连起来，今年下面写多了少了多少

钱或时间从哪挪到哪：去年、今年（或前后两周）两根长条，同一项连起来。

- `parts` 几项的名字，`a`、`b` 各一串数，跟 `parts` 一一对应。
- `hi` 强调哪一项（写名字）；`tall: true` 两根条加高，占满标题下面。

<details><summary>字段</summary>

- `parts`：一串文字，2–5 个
- `a`：一组：
  - `label`：文字
  - `v`：一串数，2–5 个
  - `src`：文字（可不写）
- `b`：一组：
  - `label`：文字
  - `v`：一串数，2–5 个
  - `src`：文字（可不写）
- `hi`：文字（可不写）
- `unit`：文字（可不写）
- `digits`：数（可不写）
- `tall`：true / false（可不写）

</details>

```yaml
type: cueshift
kicker: <什么怎么分 · 前 vs 后>
title: <总数变了多少，主要挪到了哪>
parts: [<项1>, <项2>, <项3>]
a:
  label: <前>
  v: [<数>, <数>, <数>]
  src: <出处>
b:
  label: <后>
  v: [<数>, <数>, <数>]
  src: <出处>
hi: <项2>
unit: <单位>
```

### cuepick — 提示页：两个做法，推荐的那个是主角（推荐 X＋强调色大数），另一个缩成右边对照；底下一行选它多什么，单位跟两个做法一样

两个做法选一个：推荐的那个是主角，另一个缩在右边对照，底下一行“选它多什么”。

- `plans` 正好两个，推荐的写 `pick: true`；`diff` 是两者之差，单位跟两个做法一样。
- 预测数写 `pre: 约`，精确数写 `exact`。风险、要对一下的写进 notes。
- 页面上不显示 `title`，最上面那句是 `lead`：把“推荐哪个”写进 `lead`。

<details><summary>字段</summary>

- `lead`：文字
- `plans`：一串，2 个，每个写：
  - `key`：文字
  - `name`：文字
  - `pre`：文字（可不写）
  - `v`：数或文字（原样显示）
  - `exact`：数（可不写）
  - `unit`：文字（可不写）
  - `text`：文字
  - `pick`：true / false（可不写）
  - `src`：文字（可不写）
  - `how`：文字（可不写）
- `diff`：一组：
  - `text`：文字
  - `pre`：文字（可不写）
  - `v`：数或文字（原样显示）
  - `exact`：数（可不写）
  - `unit`：文字（可不写）
  - `src`：文字（可不写）
  - `how`：文字（可不写）

</details>

```yaml
type: cuepick
kicker: <要定的事 · 两种做法>
title: <我推荐 X：多花多少，预计多什么>
lead: <引子>
plans:
- key: A
  name: <做法 A>
  v: '<数>'
  unit: <单位>
  text: <这个数是什么；要花什么>
  pick: true
  src: <怎么估的>
- key: B
  name: <做法 B>
  v: '<数>'
  unit: <单位>
  text: <…>
  src: <…>
diff:
  text: <选 A 比 B：多花多少，多来>
  v: '<数>'
  unit: <单位>
  src: <A − B>
```

### cuecalc — 推演器（提示版）：几根能拖的滑块，右边只有结果一个大数；算式和假设进备注

能拖的推演：2–4 根滑块，右边一个结果大数。对方问“要是……呢”的时候当场拖给他看。

- `params` 每根滑块：`key` 只用英文字母（公式里用它），`min`/`max`/`step`/`def` 默认值。
- `formula` 用这些 key 和 `+ - * / ( )` 写；`formulaText` 是给人看的中文算式，出现在出处里。查账会用默认值算一遍，跟标题对。
- `result.label` 结果叫什么，`unit`，`digits` 小数位；`approx: 万` 按万显示一位小数。
- `limit` 画一根上限线（比如一周 40 小时），`limitLabel` 线叫什么，结果超过线会变色。`limitLabel` 只写名字（比如“我正常一周”），后面的数和单位会自己加上，别再写一遍。
- `grid: {rows: <key>, cols: <key>, label: <一格是什么>}` 在结果下面画一片格子（行数、列数跟两根滑块走）；不写就不画。
- 同一份里有 `cueask` 写了 `gets.link: true`，请批页那个数会跟着这里拖出来的结果变。
- 页面上不显示 `title`，也没有别的判断句：结论要让人一眼看到，写进 `sub`（结果大数下面那行）。

<details><summary>字段</summary>

- `params`：一串，2–4 个，每个写：
  - `key`：文字
  - `label`：文字
  - `min`：数
  - `max`：数
  - `step`：数
  - `def`：数
  - `unit`：文字（可不写）
  - `note`：文字（可不写）
- `formula`：文字
- `formulaText`：文字（可不写）
- `result`：一组：
  - `label`：文字
  - `pre`：文字（可不写）
  - `unit`：文字（可不写）
  - `approx`：文字（可不写）
  - `digits`：数（可不写）
- `sub`：文字（可不写）
- `src`：文字（可不写）
- `grid`：见下面说明（可不写）
- `limit`：数（可不写）
- `limitLabel`：文字（可不写）
- `limitMax`：数（可不写）

</details>

```yaml
type: cuecalc
kicker: <你可以自己拖>
title: <默认值算出来的结论>
params:
- key: a
  label: <第一个能拖的数>
  min: <最小>
  max: <最大>
  step: 1
  def: <默认>
  unit: <单位>
- key: b
  label: <第二个>
  min: <…>
  max: <…>
  step: <…>
  def: <…>
  unit: <单位>
formula: a*b/60
formulaText: <中文算式>
result:
  label: <结果叫什么>
  unit: <单位>
  digits: 1
src: <默认值从哪来>
notes:
- <算法、每个默认值为什么这么定、拖给他们看的顺序>
```

### cueask — 请批（提示版）：哪天前、批哪两件、换来什么

最后一页：请对方定什么、哪天前、换来什么。

- `needs` 1–2 件，每件一个数（`v`、`unit`）一句话；`gets` 换来什么，一个数。最好写两件：只写一件时右边那一半是空的，查账会提醒一句。
- `needs` 的数是从材料里算出来的，就写 `src`（从哪来）、`how`（怎么算），按 S 能看到；是你们要请对方批的数（比如每周 5 条），不用写，查账也不追。
- 页面上不显示 `title`，最上面那句是 `lead`：请对方定什么，写进 `lead`。
- `due: 2027-01-11` 写了就画出那一周；没有截止日期就别写，也别在 lead 里编日期。
- `gets.link: true`：这个数跟着前面推演器的结果走（`linkNote` 写“推演值”之类）；`exact`、`exactUnit`、`exactDigits` 给精确值。只有推演器算出来的就是“换来的东西”（比如省下几小时、多出几单）才写 `link`；推演器算的是成本、总工时这类数时别写，`gets` 直接写换来的那个数。开了 `link`，`gets` 的 `text`、`pre` 里别写会跟着滑块变的数（比如滑块默认的“每周 5 条”）：拖了滑块，大数变了，这句话不会变，前后就对不上；写成“照这组用时”这类不带数的话，查账看到这种数会提醒。

<details><summary>字段</summary>

- `lead`：文字
- `needs`：一串，1–2 个，每个写：
  - `v`：数或文字（原样显示）
  - `unit`：文字（可不写）
  - `text`：文字
  - `src`：文字（可不写）
  - `how`：文字（可不写）
- `gets`：一组：
  - `pre`：文字（可不写）
  - `v`：数或文字（原样显示）
  - `exact`：数（可不写）
  - `unit`：文字（可不写）
  - `text`：文字
  - `src`：文字（可不写）
  - `how`：文字（可不写）
  - `link`：true / false（可不写）
  - `linkNote`：文字（可不写）
  - `exactUnit`：文字（可不写）
  - `exactDigits`：数（可不写）
- `due`：日期 2027-01-11（可不写）

</details>

```yaml
type: cueask
kicker: <要谁定的>
title: <请定：……>
lead: <一句话说为什么现在要定>
needs:
- v: '<数>'
  unit: <单位>
  text: <第一件>
- v: '<数>'
  unit: <单位>
  text: <第二件>
gets:
  text: <换来什么>
  v: '<数>'
  unit: <单位>
  src: <怎么来的；估算写明是估算>
notes:
- <没定的、待定的、风险>
```

## 图表页（18 种）

例子来自一份老师学期总结样张：**示例，人物、数据均为虚构**，只看写法。

### cover — 封面：一个大数 + 两张三层卡（期初期末、另外几个数）+ 每周走势

- `big`：一组：
  - `sign`：文字（可不写）
  - `v`：数或文字（原样显示）
  - `unit`：文字（可不写）
  - `src`：文字（可不写）
  - `how`：文字（可不写）
- `from`：一组：
  - `label`：文字
  - `v`：数或文字（原样显示）
  - `src`：文字（可不写）
- `to`：一组：
  - `label`：文字
  - `v`：数或文字（原样显示）
  - `src`：文字（可不写）
- `kpis`：一串，2–3 个，每个写：
  - `label`：文字
  - `a`：数或文字（原样显示）
  - `b`：数或文字（原样显示）
  - `unit`：文字（可不写）
  - `src`：文字（可不写）
- `ftCard`：一组（可不写）：
  - `label`：文字
  - `tag`：文字（可不写）
  - `say`：文字（可不写）
- `kpisCard`：一组（可不写）：
  - `label`：文字
  - `say`：文字（可不写）
  - `note`：文字（可不写）
- `bridge`：文字（可不写）
- `weeks`：一串数，6–31 个
- `weeksLabel`：文字（可不写）
- `weeksSrc`：文字（可不写）

### trend — 趋势：一条线，标出转折、两段平均、一个低谷

- `unit`：文字（可不写）
- `weeks`：一串数，6–31 个（可不写）
- `event`：一组（可不写）：
  - `at`：数
  - `text`：文字
- `avg`：一串，2 个（可不写），每个写：
  - `from`：数
  - `to`：数
  - `label`：文字
- `dip`：一组（可不写）：
  - `at`：数
  - `text`：文字
- `src`：文字（可不写）

<details><summary>例子（示例）</summary>

```yaml
type: trend
kicker: 每周小测 · 班级平均分
title: 第 6 周起，周测平均分一路往上走，第 18 周到 83.2
stand: 前 5 周一直在 71 分上下。第 6 周开始用 AI 出三档练习，之后 13 周里有 10 周比上一周高。
unit: 分
event:
  at: 6
  text: 第 6 周 · 开始用 AI 出三档练习，我来挑题
avg:
- from: 1
  to: 5
  label: 第 1–5 周平均
- from: 14
  to: 18
  label: 第 14–18 周平均
dip:
  at: 12
  text: 第 12 周 · 期中后放了 5 天假
src: 周测登记表 · 第 1–18 周 · 每周 46 人平均
```

</details>

### target — 目标对照：每个目标一行，做到没做到一眼看出

  - `target`：数
  - `actual`：数
  - `unit`：文字（可不写）
  - `lower`：true / false（可不写）
  - `dg`：数（可不写）
  - `src`：文字（可不写）
- `miss`：文字（可不写）
- `missOn`：文字（可不写）

<details><summary>例子（示例）</summary>

```yaml
- label: 80 分以上人数
  target: 28
  actual: 31
  unit: 人
  src: 成绩册 · 期末 ≥80 分 31 人
- label: 作业按时交
  target: 90
  actual: 93

```

</details>

  - `agg`：文字（可不写）
  - `src`：文字（可不写）
- `vs`：文字（可不写）

### bridge — 拆解桥：从起点一步步走到终点，每步多少

- `start`：一组：
  - `label`：文字
  - `v`：数
  - `src`：文字（可不写）
- `end`：一组：
  - `label`：文字
  - `v`：数
  - `src`：文字（可不写）
- `steps`：一串，2–6 个，每个写：
  - `label`：文字
  - `v`：数
  - `note`：文字（可不写）
  - `src`：文字（可不写）
  - `a`：数（可不写）
  - `b`：数（可不写）
  - `pct`：true / false（可不写）
  - `inv`：true / false（可不写）
  - `rest`：true / false（可不写）
- `unit`：文字（可不写）
- `kind`：文字（可不写）
- `scale`：数（可不写）
- `negOn`：文字（可不写）

<details><summary>例子（示例）</summary>


### argue — 论证：一个主张 + 三条依据 + 一条反方和回应

- `claim`：文字
- `evidence`：一串，3 个，每个写：
  - `n`：文字
  - `tag`：文字
  - `big`：数或文字（原样显示）
  - `unit`：文字（可不写）
  - `text`：文字
  - `detail`：文字（可不写）
  - `bars`：一串[名字, 数, 显示的字]（重点那根加第 4 个 1），2–3 个
  - `src`：文字（可不写）
- `counter`：一组（可不写）：
  - `q`：文字
  - `a`：文字
  - `src`：文字（可不写）

<details><summary>例子（示例）</summary>

```yaml
type: argue
kicker: 为什么说是新做法带来的
title: 分数涨了 11.8 分，三条依据说明主要是新做法的作用
stand: 最容易被问的一句是“会不会是卷子变简单了”。下面三条依据，加一条反方和回应。
claim: 主要是第 6 周起换的出题和批改办法带来的，不是卷子变简单
evidence:
- n: '01'
  tag: 同一张卷子
  big: '+11.8'
  unit: 分
  text: 我班比另外 3 个班多涨 9.7 分
  detail: 初一 4 个班考同一张期末卷
  bars:
  - [我班, 11.8, '+11.8']
  - [另 3 班平均, 2.1, '+2.1']
  src: 教务处成绩汇总 · 初一 4 个班 · 同卷
- n: '02'
  tag: 时间对得上
  big: 第 6 周
  text: 分数从换办法的那一周开始往上走
  detail: 之前 5 周一直在 71 分上下
  bars:
  - [第 1–5 周, 71.3, '71.3']
  - [第 14–18 周, 81, '81.0', 1]
  src: 周测登记表 · 第 1–18 周
- n: '03'
  tag: 分项拆开
  big: '+9.8'
  unit: 分
  text: 涨的分大多在阅读和写作两块
  detail: 正是新办法管的两块：分层练习和作文批改
  bars:
  - [阅读, 5.2, '+5.2']
  - [写作, 4.6, '+4.6']
  - [其他, 2, '+2.0']
  src: 成绩册 · 分题型小分
counter:
  q: 会不会是我班底子差，本来就更好涨？
  a: 期初我班 71.4 分，年级平均 72.0 分，起点差不多
  src: 教务处 · 9 月期初测年级汇总
```

</details>

<details><summary>例子（示例）</summary>

### process — 流程：几步，每步谁做、花多久，标出最关键的一步

- `steps`：一串，3–5 个，每个写：
  - `day`：文字
  - `who`：文字
  - `text`：文字
  - `time`：文字
  - `note`：文字（可不写）
  - `key`：true / false（可不写）
- `why`：文字（可不写）
- `otherLabel`：文字（可不写）

<details><summary>例子（示例）</summary>

```yaml
type: process
kicker: 每周怎么做 · 4 步
title: 每周 4 步，第 2 步只要 25 分钟，却最省不得：我把 AI 出的题删改一遍
stand: AI 出题很快，但第一版总有答案不唯一、超纲的词。第 2 步省不得。
steps:
- day: 周一
  who: AI
  text: 照这周的课文出三档题
  time: 10 分钟
  note: 我写一段提示，附上课文和学生上周错得多的题
- day: 周二
  who: 我
  text: 删改题目，定稿
  time: 25 分钟
  note: 删答案不唯一的、超纲的；每档留 5、7、9 题
  key: true
- day: 周三
  who: 学生
  text: 按自己的档做
  time: 课上 15 分钟
  note: 自己选档，做完可以往上一档挑战
- day: 周五
  who: AI＋我
  text: AI 先标错，我批结构
  time: 1 小时 55 分
  note: AI 标语法和拼写，按类型归好；我只看结构和内容
```

## 不能用的 6 种

下面这几种还带着样张里写死的字，放别人的内容会带出去。查账遇到会报“错”，并说换成什么：

- `calc`：推演器换成 cuecalc
- `compare`：前后对比换成 cue3（v 写成“92 → 143”）或 cueshift
- `heat`：每周走势换成 cueline，或 cue 加 strip（kind: bars）
- `voices`：原话换成 quote
- `gantt`：时间安排写进 cueask 的 needs 和 due，或者用 process
- `gallery`：这个页型画的是练习单，不能放图片，先不用
