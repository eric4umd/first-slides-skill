# eric-first-slides：材料 → 能讲的幻灯片

这一份写给你（做幻灯片的 AI）看。

## 用户要做的事

1. **放材料**：把材料放进一个文件夹，或者直接发给你。
2. **让你装上这个 Skill**：发给你仓库链接和一段话，或者一张写着这两样的截图。
3. **说一句要做什么**：比如“帮我用这些做一套年终述职”。
4. **打开结果**：你做完替他打开；他也可以双击那个 `.html` 文件。

除此之外的事都由你来做：装 Skill、看电脑上能不能运行、缺什么装什么、写稿、生成、检查、打开。用户不碰命令行，不看代码，也不改稿子的格式。

**跟用户说话时**，不说 YAML、构建、终端、命令行、脚本、Python、venv、依赖、报错原文这类词。要说就说“我先看看你电脑上能不能直接做”“我整理一下稿子”“生成好了，已经帮你打开”。真要用户点一下系统弹窗，就照实告诉他点哪个按钮（见“环境”）。

## 这个 Skill 里有什么

| 路径 | 是什么 |
|---|---|
| `scripts/build.py` | 唯一入口：读 content.md，查账，生成一个 HTML 文件 |
| `engine/` | 幻灯片引擎（生成时整份嵌进 HTML，结果不联网也能放） |
| `references/content写法.md` | **先读**：从材料到 content.md 怎么想、怎么排、数怎么写 |
| `references/页型库.md` | 每种页型什么时候用、写哪些字段、空白骨架 |
| `examples/` | 一份完整的 content.md **示例**（人物、公司、数字都是虚构的），只看写法，别把里面的人名、数字、结论放进用户的幻灯片 |
| `fonts/` | Inter、思源黑体（Noto Sans SC），SIL Open Font License，许可文件在 `fonts/OFL-*.txt` |

这里只有一种样子：浅色、干净、数字为主角（叫“精确”）。没有别的风格可选，别答应用户换风格、出 PPT 文件或 Keynote 文件。

## 装这个 Skill 的时候

用户发来链接和一段话（或者它们的截图）时：

1. 截图里的链接看不清，请用户把链接用文字发一遍。
2. 下载仓库，读根目录的 `README.md` 和这份 `SKILL.md`。
3. 把 `eric-first-slides` 这个文件夹整个放进你这个工具放 Skill 的地方。不知道放哪，先看你这个工具自己的说明；还是不确定，用一句话问用户。别覆盖已经有的同名文件夹，有的话先告诉用户。
4. 照下面“看环境”和“环境”两节，把能运行的条件配好。
5. 用示例试一次：把 `examples/示例1_市场部年终述职/content.md` 复制到一个新的临时文件夹再生成，别在 Skill 文件夹里生成。这一次**不带 `--open`**，只生成，不弹浏览器。生成没报错、HTML 文件在，就算装好；能看网页截图的话再看一眼第一页。告诉用户这个文件在哪、叫什么，他想看就双击打开。
6. 用一两句话告诉用户：装好了，接下来把材料放进一个文件夹，跟你说一句要做什么。

## 流程

### 1. 看环境（用户无感）

先看这台电脑有没有能用的 Python。别假设你这个工具自带 Python，也别假设它能在用户目录里建东西，都试一下再说。Mac 上先照“环境”里“看 Python 能不能用”那三步走，别一上来就运行 `python3`。能用了再运行：

```
python3 <本Skill>/scripts/build.py --doctor
```

它会用一两句话说明：这台电脑的 Python 能不能用，字体走哪条路。**只要 Python 3.8 以上，就能做**，什么都不用装。细节和缺 Python 时怎么办，见下面“环境”。

### 2. 读材料，写 content.md

照 `references/content写法.md` 做：材料全读完 → 锁“对谁说、要他做什么、靠哪几个数” → 排页 → 写字 → 数一个个对上材料。页型和字段查 `references/页型库.md`，或者运行 `build.py --types`。

- 在用户的材料文件夹里新建一个“幻灯片”文件夹，content.md 放在里面：`<材料文件夹>/幻灯片/content.md`。中文路径没问题。
- 页数、内容、要不要放能拖的推演页，都跟着用户的材料走。示例里有几页、有几个滑块，跟用户这一份无关。
- 写用户这一份时别打开示例照着改。示例只在装 Skill 时试做一次，写法有疑问查 `references/`。页数、标题、排法都从用户的材料来。
- 材料里推不出来的事，标“待定”写进备注，接着把能定的部分做完，最后一起用一两句话问用户；别编，也别做到一半停下来问。用户明说了要你先问，才先问。

### 3. 查账

```
python3 <本Skill>/scripts/build.py <路径>/content.md --check
```

- 有“错”：照提示改 content.md，再查，直到没有“错”。
- 有“提醒”：一条条看，能改就改，不改要说得出理由。
- 查账写在 content.md 旁边的 `…_查账.md` 里，名字跟下一次生成的 HTML 一样。比如已经有 `…_v2.html`，只查账时写成 `…_v3_查账.md`，旁边暂时没有 `_v3.html`，生成以后就对上了。连着只查账几次，留最新一次。
- 标题里的数是几项加起来的（比如 3 件事一共 34 小时），查账会提醒“找不到”。把这几项写进这一页的数据，查账就能算；写不进去的，回材料把这几项加一遍，对上了就留着，告诉用户是哪几项加的。
- 查账只核能算的那部分：加起来对不对、前后差多少、推演器算出来多少、标题里的数在这页数据里找不找得到。单独摆在页面上的一个数（比如提示页、三格页上的大数），它没法跟材料原件对。所以“提醒 0”不等于每个数都对：页面上每个数，你都要回材料里再对一遍。
- 句子里你自己算出来的数（notes、sub 里的加减、把分钟换成小时），查账也看不到，写完自己再算一遍。

### 4. 生成并打开

```
python3 <本Skill>/scripts/build.py <路径>/content.md --open
```

- 生成的 HTML 和 content.md 在同一个文件夹里，文件名取自 content.md 开头的 `deck` 和 `who`。
- 同名 HTML 已经有了，不会覆盖，新文件自动叫 `…_v2.html`、`…_v3.html`；告诉用户打开最新那个。只查账不占号。
- `--open` 会真的在这台电脑的默认浏览器里弹出这个文件；不带 `--open` 就只生成、不打开。它说“已用默认浏览器打开”，只说明打开这一步成功了，看不出页面显示得对不对。打不开时它会说文件在哪，你把这句转成“我做好了，在 XX 文件夹里，双击 XX 就能打开”告诉用户。
- 每次都告诉用户这次的文件名。你这个工具要是自带预览窗，别只靠它：预览窗可能还开着上一次的同名文件。
- 你能看网页截图的话，打开以后从头翻一遍（→ 键），看有没有字挤出去、数显示得不对。看不了的话，交给用户时请他从头翻一遍，哪页字挤了、哪个数不对，告诉你第几页。

### 5. 交给用户

用户要改：改 content.md → 查账 → 生成，告诉他新文件名。

用户说“第几页的标题”，指的是他在那一页上看到的那句大字，改完他要能在页面上看出变了。各页型页面上显示哪几个字段，见 `references/页型库.md` 开头。cueask、cuepick 两种页面上那句是 `lead`，cuecalc 页面上没有判断句（`title` 只在讲者窗口和手机版里出现）：用户要改这几页的标题，改 `lead`（cuecalc 改 `result.label` 或 `sub`），`title` 跟着改成同一个意思。改完告诉他改的是页面上哪一句。

交给他的时候，用大白话说下面几句（挑他用得上的）：

- “双击这个文件就能打开，不用联网。按 → 或空格往下讲，← 往回。”
- “按 F 全屏，再按一次或者按 Esc 退出。”
- “按 N 能看到这一页我帮你写的讲稿和要点，再按一次收起。它就显示在幻灯片上，自己练的时候用；对着别人讲时别按，用下面的 D。”
- “要投影或者在会议里共享屏幕，先按 D：会多开一个讲者窗口，里面有讲稿、下一页和计时，两个窗口一起翻。原来那个窗口放到投影上，或者共享时只选原来那个窗口，别共享整个屏幕，不然讲稿会被看到。”
- “有人问某个数从哪来，按 S，标了出处的数都列在上面，有算法的也写着；鼠标停在数上也能看到。”
- “按 B 先黑屏，再按一次回来。”
- 有“待定”的地方，一句话问他。

## 环境

**最少要装的**：Python 3.8 或以上。读稿子用的 PyYAML 已经放在 Skill 里，字体也事先裁好了一份常用字，所以不装别的也能出一个能打开的文件（约 3 MB）。

装任何东西之前，先用一句白话告诉用户要装什么、为了什么，他点头再装；他不想装就不装，照常做。用户说“缺的话你来装”，指的只是“最少要装的”；下面“可选”的两样不算缺，要装先问一句。

**可选**（文件更小，约 1 MB）：fontTools 和 brotli。只装在用户目录下的虚拟环境里，不要装进系统的 Python，不要用全局 `pip install`、不要 `sudo`：

```
python3 -m venv ~/.eric-first-slides/venv
~/.eric-first-slides/venv/bin/python -m pip install fonttools brotli
~/.eric-first-slides/venv/bin/python <本Skill>/scripts/build.py <路径>/content.md --open
```

装不上（没网、被拦）就不装，照常用 `python3` 生成。

**字体的三条路**（`--font`，默认 `auto` 自动选）：有 fontTools 就只裁用到的字；没有就用事先裁好的常用字；常用字里没有的个别字会列出来，那几个字用电脑自带字体显示。两样都不行时用电脑自带字体，照样能打开，只是样子差一些，生成时会说一句。

**看 Python 能不能用**（macOS，三步）：

1. 运行 `command -v python3`，看 `python3` 在哪。什么都没出来，就是没有，走下面 A。
2. 它在 `/usr/bin/python3`（系统自带的那个）时，先运行 `xcode-select -p`。没输出就别运行它：它会弹一个“安装命令行开发者工具”的系统窗口，走下面 A 或 B。有输出只说明这个窗口不会弹，不说明 Python 一定能用，接着第 3 步。
3. 运行 `python3 --version`。3.8 或以上就能用；低于 3.8、报错，走下面 A。

别的地方的 `python3`（比如 `/usr/local/bin`、`/opt/homebrew/bin`）不会弹窗，直接第 3 步。

**没有 Python 3.8+ 时**：

- macOS：两条路，选一条：
  - **A（推荐，不用管理员密码）**：先问用户“你电脑上缺一个运行用的小工具，我从网上下载，装到你自己的用户文件夹里，不改你电脑原来的设置，也不用你操作，可以吗？”（装在 `~/.local/bin`），他同意后再
    `curl -LsSf https://astral.sh/uv/install.sh | env UV_NO_MODIFY_PATH=1 sh`（`UV_NO_MODIFY_PATH=1` 让它不改 shell 的配置文件；后面都写完整路径 `~/.local/bin/uv`，用不着改），
    `~/.local/bin/uv python install 3.12`，
    `~/.local/bin/uv venv ~/.eric-first-slides/venv --python 3.12`，
    之后都用 `~/.eric-first-slides/venv/bin/python` 运行。要装 fontTools 就 `~/.local/bin/uv pip install --python ~/.eric-first-slides/venv/bin/python fonttools brotli`。需要联网。
  - **B**：让用户在弹出的窗口里点“安装”，等它装完（要等一阵，可能要输开机密码）。这是用户要多做的一件事，照实告诉他。
  - 别的装法：python.org 的安装包要输管理员密码；电脑上还没有 Homebrew 的话，装 Homebrew 本身也要。已经有 Homebrew 的，`brew install python` 通常不用密码，但会动 Homebrew 管着的东西，先问用户。这几种都没在真机上比过，默认先走 A。
  - 上面 A、B 两条路**都没在真机上验证过**。别向用户保证“几分钟就好”“一定装得上”；装不上就照实说卡在哪一步。
- Linux：一般自带 python3；没有就走上面 A。
- Windows：**没测过**。用 `py -3` 代替 `python3` 理论上能跑，别向用户保证。

所有出错提示都是一句中文，说的是下一步该做什么；照做就行。
